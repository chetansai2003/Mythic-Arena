# Architecture decisions

1. **JavaScript throughout.** The user's direction supersedes TypeScript in the supplied PDFs. Source is JS/JSX with ES modules. Zod checks untrusted boundaries; ESLint, module validation, tests, and production builds replace the TypeScript gate. No misleading `typecheck` script.
2. **Specification precedence.** The six-part plan overrides the earlier architecture and visual blueprint. RULES.md freezes version 1 and identifies rule clarifications. Each part stops at its evidence gate.
3. **Workspace.** npm workspaces; React/Vite/Tailwind frontend; Redux Toolkit for shared preferences; Express API; independent worker lifecycle; browser-safe shared schemas; pure game-engine package implemented in Step 3. No competing client store.
4. **Runtime.** Node 22.17.0 and npm 10.9.2 match the verified local runtime. Node 22 is an LTS line. Vite 8 requires Node 20.19+ or 22.12+, so the installed runtime is compatible. Exact dependencies are recorded in package manifests and package-lock.json. Review runtime security updates before a production release.
5. **Scope honesty.** Part 2 replaces account/deck previews with real authenticated persistence. Step 3 adds local practice against a bot. Step 4 adds real online battles, persisted history, and the wins leaderboard. There are no fabricated wins or active matches.
6. **Data and concurrency.** Redis owns active state; MongoDB owns durable records. Step 4 action correctness uses atomic version checks, deduplication, and a result outbox, not lock leases alone. Stored deadlines and a worker replace expiration notifications. No gameplay jobs run in Part 1.
7. **Local infrastructure.** Compose is the canonical full-stack setup. MongoDB uses a single-node replica set with an idempotent initializer. Containers resolve `mongo`; host development uses directConnection=true against the published loopback endpoint. Persistent development volumes survive ordinary shutdown. This local configuration is not a production security profile.
8. **Private contracts.** Strict schemas reject extra properties; distinct self/opponent shapes reduce accidental leaks. They are not a substitute for the engine projection and network leakage tests required in later parts. Identity never comes from client commands.
9. **Accessibility.** Essential actions remain HTML. Dialogs use the native modal dialog focus model. System reduced motion cannot be overridden by a more animated user preference. Step 5 adds optional 3D while preserving the shell's static visual fallback.
10. **Health.** Liveness is dependency-independent. Readiness uses bounded dependency checks and fails during shutdown. Public responses expose dependency status only; logs exclude raw request bodies, headers, configuration values, and error messages that could contain credentials.
11. **Verification.** Vitest collects unit/component tests separately from integration tests; Playwright owns browser tests. Integration and browser data use unique namespaces. Actual results and unavailable checks are recorded in each part's report, never inferred from code existence. Browser cleanup runs in a separate native Node process to avoid Playwright's module-loader interaction with the MongoDB driver.
12. **Identity.** Part 2 uses Argon2id, memory-only access tokens, opaque hashed refresh credentials, transactional rotation, family revocation, signed CSRF cookies and explicit origins. Auth mutations are serialized in the browser where Web Locks are available. Logout revokes both the cookie family and the presented valid access-token family if they differ.
13. **Catalog and decks.** Twenty immutable version-1 definitions are seeded by an explicit job. All cards have implemented behavior as of Step 3 and are available for practice; online availability is separate. Decks are saved only with valid 30-card composition; partial drafts remain in the tab. Revision-checked writes prevent silent overwrites.
14. **Operation deadlines.** Dependency health probes have a 1.2-second bound. MongoDB operations use a separate ten-second socket timeout so index creation and transactions are not constrained to a health-probe budget. Client requests also have a ten-second deadline and preserve unconfirmed drafts.

Official compatibility references: [Node releases](https://nodejs.org/en/about/previous-releases), [Vite requirements](https://vite.dev/guide/), [Playwright CI](https://playwright.dev/docs/ci).

15. **Practice authority.** The local adapter owns private state in one tab, publishes allowlisted snapshots, and never writes wins. It is replaceable by a server transport in Step 4. Browser code is inspectable; local practice is not an online trust boundary.
16. **Deadline precedence.** Engine commands first catch up due turn deadlines. A stale command may be rejected alongside an independently advanced timer state; callers must preserve that candidate. Other rejected commands return unchanged state. Turn transitions use scheduled times, not delayed worker arrival times.
17. **Step 3 visuals.** The 2D board uses keyboard-operable buttons, explicit legal targets and horizontal rows on small screens. Only accepted events trigger a brief status pulse; restores do not replay it. Reduced motion disables the pulse. Practice is lazy-loaded.

18. **Online authority.** Redis stores frozen decks as opaque JSON inside Lua reservations to preserve empty nested arrays. All game mutations compare-and-set the complete record and store accepted-action fingerprints/receipts atomically. The worker rechecks durable deadlines and writes transactional MongoDB receipts. Browser transport uses WebSocket so same-origin handshakes retain the mandatory Origin header.
19. **Online test isolation.** Browser viewport journeys run serially because they share one casual queue. Service tests use isolated namespaces; fault tests terminate only child processes created for the test.

20. **Renderer compatibility.** React Three Fiber 9.7.0 declares React >=19 <19.3. Step 5 aligns React and ReactDOM to 19.2.8 and pins Three 0.186.0, Drei 10.7.8, Motion 13.2.0 and GSAP 3.15.0 in the frontend. Peer conflicts are resolved rather than ignored.
21. **Progressive visuals.** High graphics lazily imports an original instanced arena. Low and reduced motion use static SVG. Optional WebGL failure cannot gate navigation, readiness or moves. Hardware pixel ratio is capped at 1.25; detected software rendering uses 0.65. Hidden tabs pause and offscreen scenes unmount. A build check limits compressed arena plus GSAP payloads to 5 MB.
22. **Animation authority.** The presentation layer consumes public snapshots and accepted IDs only, skips gaps/stale events, and has no effect backlog. GSAP contexts cancel on unmount or motion changes. Stronger summon styling does not add a new ultimate command or alter immutable card definitions. Audio uses original local tones and starts muted.
23. **Production and security boundary.** Production deployment separates app containers from cloud-managed databases (`deploy/compose.production.yml`). Bundled database containers are prohibited in production. Client bundles are scanned to ensure no secrets or backend database connection strings are shipped. Application loggers strictly redact authentication credentials and tokens.
24. **Operational and scale honesty.** Load testing benchmarks the declared target of 100 simultaneous players across 50 matches; actual observed metrics are recorded without assumed scale. The MVP is not claimed to be horizontally distributed across multi-region WebSocket servers without a tested distributed adapter. Match draining prevents in-flight game loss during rolling updates.
